>

## 0. 大原則

### 0.1 通り名はただのラベル。ロジックは添字で動く

**通り名に依存する処理を書かないこと。** すべて `index` で計算する。

これにより、実際の京都の通り名（烏丸通・四条通…）が確定していなくても
v1 の全機能が完成させられる。最後に名前テーブルを差し替えるだけでよい。

### 0.2 v1 は緯度経度を一切使わない

座標フィールドは契約に存在しない。GPS も地図も使わない。

## 1. 座標系（グリッド）

京都の碁盤の目を、2本の軸の**添字**で表す。

| 軸 | 意味 | 添字の向き | 仮の表示名 |
|---|---|---|---|
| `ns` | 南北に走る通り（縦） | **0 = 最も東**、増えるほど西 | `A通`, `B通`, `C通` … |
| `ew` | 東西に走る通り（横） | **0 = 最も北**、増えるほど南 | `1通`, `2通`, `3通` … |

> 添字の向きは京都の数え歌の順（北→南 / 東→西）と一致させてある。
> 実データを入れる際もこの順を守ること。

### 1.1 方向と添字の対応

| 表記 | 方角 | 添字の変化 |
|---|---|---|
| `上ル` | 北 | `ew_index - 1` |
| `下ル` | 南 | `ew_index + 1` |
| `東入ル` | 東 | `ns_index - 1` |
| `西入ル` | 西 | `ns_index + 1` |

## 2. 型定義

### 2.1 Street

```json
{
  "id": "ns-03",
  "axis": "ns",
  "index": 3,
  "name": "D通"
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | `"{axis}-{index:02d}"`。安定した識別子 |
| `axis` | `"ns"` \| `"ew"` | 軸 |
| `index` | int | 0 始まり。1章の向きに従う |
| `name` | string | **表示専用。**ロジックで使わない |

### 2.2 Intersection

```json
{ "ns": "ns-03", "ew": "ew-07" }
```

南北の通りと東西の通りの組。これだけで位置が一意に決まる。

### 2.3 Direction

```
"上ル" | "下ル" | "東入ル" | "西入ル"
```

### 2.4 Bearing（8方位）

```
"北" | "北東" | "東" | "南東" | "南" | "南西" | "西" | "北西"
```

京都タワーがどちらに見えるかを表す。添字の比較のみで算出する（SPEC 4.8.3）。

## 3. エンドポイント

ベースパス: `/api`

### 3.1 `GET /api/grid`

グリッドの定義を返す。フロントは起動時に1回だけ呼ぶ。

**レスポンス**

```json
{
  "ns_streets": [
    { "id": "ns-00", "axis": "ns", "index": 0, "name": "A通" },
    { "id": "ns-01", "axis": "ns", "index": 1, "name": "B通" }
  ],
  "ew_streets": [
    { "id": "ew-00", "axis": "ew", "index": 0, "name": "1通" },
    { "id": "ew-01", "axis": "ew", "index": 1, "name": "2通" }
  ],
  "exists": [
    [true,  true,  false],
    [true,  true,  true ]
  ],
  "tower": { "ns": "ns-05", "ew": "ew-15" }
}
```

| フィールド | 説明 |
|---|---|
| `ns_streets` | 南北の通り。`index` 昇順（東→西） |
| `ew_streets` | 東西の通り。`index` 昇順（北→南） |
| `exists` | **実在マスク。**`exists[ew_index][ns_index]` が `false` なら交差点が存在しない |
| `tower` | 京都タワーが立つ交差点 |

> `exists` の添字順に注意。**行 = ew（横の通り）、列 = ns（縦の通り）** で、
> 画面上の見た目と一致する。

---

### 3.2 `POST /api/route`

現在地と目的地から、経路候補と指示文を生成する。

**リクエスト**

```json
{
  "from": { "ns": "ns-05", "ew": "ew-11" },
  "to":   { "ns": "ns-02", "ew": "ew-07" }
}
```

**レスポンス**

```json
{
  "from": { "ns": "ns-05", "ew": "ew-11" },
  "to":   { "ns": "ns-02", "ew": "ew-07" },
  "start": {
    "tower_visible": true,
    "tower_bearing": "南",
    "hint": "京都タワーが南に見えます。背にして立ってください。"
  },
  "routes": [
    {
      "id": "r1",
      "visible_ratio": 0.75,
      "turns": 1,
      "steps": [
        {
          "direction": "上ル",
          "count": 4,
          "to_street": "ew-07",
          "to_street_name": "8通",
          "instruction": "京都タワーを背にして、4本上ル（8通まで）",
          "tower_visible": true,
          "tower_bearing": "南"
        },
        {
          "direction": "東入ル",
          "count": 3,
          "to_street": "ns-02",
          "to_street_name": "C通",
          "instruction": "8通を右手に3本東入ル（C通まで）",
          "tower_visible": false,
          "tower_bearing": "南西"
        }
      ]
    }
  ]
}
```

#### routes

経路は**1つに絞らない**（SPEC 3.5）。良い順に並べて返す。**先頭が推奨経路。**

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 経路の識別子 |
| `visible_ratio` | float | 経路上でタワーが見える交差点の割合（0.0〜1.0） |
| `turns` | int | 曲がる回数 |
| `steps` | Step[] | 手順 |

#### Step

| フィールド | 型 | 説明 |
|---|---|---|
| `direction` | Direction | 進む向き |
| `count` | int | 何本進むか |
| `to_street` | string | 到達する通りの `id` |
| `to_street_name` | string | 到達する通りの表示名 |
| `instruction` | string | **表示用の完成した日本語文。**フロントはこれをそのまま出す |
| `tower_visible` | bool | この手順の開始地点でタワーが見えるか |
| `tower_bearing` | Bearing | 開始地点から見たタワーの方角 |

> **`instruction` の文面はバックエンドが作る。**
> フロントで文章を組み立てないこと（表現を1箇所に集約するため）。

### 3.3 `POST /api/arrival` — 優先度低

到着した交差点を受け取り、目的地とのズレを講評する（SPEC 2.3）。

**リクエスト**

```json
{
  "target": { "ns": "ns-02", "ew": "ew-07" },
  "actual": { "ns": "ns-03", "ew": "ew-07" }
}
```

**レスポンス**

```json
{
  "correct": false,
  "off_by": { "ns": 1, "ew": 0 },
  "comment": "一本西入ってはりました。正解はC通どす。"
}
```

> v1 では後回しでよい。フロントは画面だけ用意して未接続でも可。

---

## 4. エラー

```json
{ "error": "INTERSECTION_NOT_FOUND", "message": "その交差点は存在しません" }
```

| コード | 発生条件 |
|---|---|
| `INTERSECTION_NOT_FOUND` | `exists` が false の交差点を指定された |
| `SAME_LOCATION` | `from` と `to` が同一 |
| `INVALID_STREET_ID` | 未知の street id |

## 5. 並行開発のための取り決め

### 5.1 モックデータ

`mock/grid.json` と `mock/route.json` に、**上記スキーマに完全準拠したサンプル**を置く。

- **フロントはバックエンドの完成を待たずに、このJSONを読んで開発する**
- バックエンドは、このJSONと同じ形を返すことをテストで保証する

### 5.2 仮のグリッドサイズ

| 軸 | 本数 | 仮の名前 |
|---|---|---|
| `ns`（縦） | 12 | `A通` 〜 `L通` |
| `ew`（横） | 16 | `1通` 〜 `16通` |

京都タワー: `ns-05` × `ew-15`（南端付近の中央）

> 実際の京都の通り名・本数は後から差し替える。
> **本数が変わっても壊れないコードを書くこと。**

### 5.3 契約変更の手順

1. このファイルを更新する
2. `mock/*.json` を更新する
3. 双方に共有する

**片方の都合で勝手に変えない。**
