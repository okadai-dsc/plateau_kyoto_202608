> 最終更新: 2026-08-08

## 1. コンセプト

**Kyoter**（New Yorker ならぬ Kyoter）

> **地図を見ずに、目的地まで到達する。**

京都の住所システムそのものをナビゲーション言語として使う。緯度経度も地図も使わず、
「上ル×3、東入ル×2」だけで目的地にたどり着く体験をつくる。

### 成立させている2本の柱

#### ① 経路の表現 = 京都の住所文法

京都は碁盤の目状で、住所が「交差点名 + 方向」で表現される。

| 表記 | 方向 |
|---|---|
| 上ル（あがる） | 北 |
| 下ル（さがる） | 南 |
| 東入ル（ひがしいる） | 東 |
| 西入ル（にしいる） | 西 |

これを使うと、経路を `上ル×3 → 東入ル×2` と表現できる。**京都でだけ成立する経路記法。**

#### ② 方位の取得 = 京都タワー

①は「自分が今どちらを向いているか」が分からないと使えない。
そこでコンパスの代わりに**京都タワー**を使う。

京都タワーは烏丸通上・京都駅北、つまり洛中のほぼ南端にある。
→ **タワーが見える方向 ≒ 南** → 上下東西がすべて確定する。

#### ③ PLATEAU の役割 = ②が成立する場所の事前計算

タワーは常に見えるわけではない（建物で遮蔽される）。
そこで PLATEAU の建物モデルから **逆可視領域（reverse viewshed）** を事前計算する。

- 視点 = 京都タワー頂部（塔頂 131m / 展望室 GL+100m）
- 対象 = 歩行者目線 1.5m
- 出力 = 地点ごとに `{可視/不可視, 方位角, 仰角, 見え方（全体/上部のみ）}`

これを経路探索に組み込むことで **「方位を見失わない経路」を選べる**。
ここが本企画の技術的な核。

## 2. 設計上の発見

### 2.1 命令文はランドマーク基準の回転で書ける

方位（北/南/東/西）を直接言う必要はない。

> 「京都タワーを**背にして**、3本上ル。**右手**に2本入ル。」

ユーザーは方位を知る必要すらない。これが最も Kyoter らしい文法。

### 2.2 GPS は「使う / 使わない」ではなく「いつ使うか」

| フェーズ | GPS | 方針 |
|---|---|---|
| スタート時 | **使う** | 初期位置の確定。ただし地図は出さず「現在地：四条烏丸」とテキストのみ |
| 道中 | **使わない** | ここがコンセプト。追従した瞬間ただのナビになる |
| ゴール時 | **使う** | 答え合わせ |

京都では交差点名がそのまま住所なので、本来は手入力（南北通り × 東西通り を選択）が最も自然。
ただし初回の観光客にはハードルが高いため、
**GPSで「今ここですね？」と候補提示 → ユーザーが確認** を主動線とし、手入力も残す。

> GPSの緯度経度から交差点を割り出す方法は **4.6** を参照。

### 2.3 到達判定は「合否」ではなく「演出」

体験の山場は着いた瞬間ではなく、
**着いたか分からないまま歩いて「合ってた！」となる瞬間**。

ただし本企画はゲームではなく観光の移動手段（3.1参照）なので、スコアで競わせない。
ズレは ✗ ではなく**京都語で講評する**。

> 「一本西入ってはりました」
> 「烏丸通で止まらはったけど、正解は室町通どす」

**ギブアップボタン（＝地図を見る＝観光客に戻る）** がコンセプト上の敗北条件になる。

> **優先度: 低。** コアではなく演出。v1では後回しでよい。

### 2.4 ランドマークはレイヤ化する

京都タワーが見えないときは他のランドマークで代用する。
山は遠く建物に遮られにくいため、**可視領域がタワーより圧倒的に広い**と見込まれる。

| レイヤ | ランドマーク | 特性 | 与える方位 |
|---|---|---|---|
| **L1** | 京都タワー | 点・高精度・可視域は狭い見込み | 南 |
| **L2** | 大文字（如意ヶ嶽）/ 比叡山 / 東寺五重塔 | 点として使える・可視域広い | 東〜北東 / 北東 / 南西 |
| **L3** | 東山連峰の稜線 | 面・低精度だがほぼ全域から見える | 東 |

地点ごとに「使える最上位のランドマーク」を提示する。
**山の可視判定には PLATEAU の地形データ(dem) が必須。**

### 3.3 対象エリア

通り名住所が成立するのは洛中。

- 北: 北大路通
- 南: 十条通（京都タワー / 京都駅を含める）
- 東: 東大路通（以東は東山で碁盤が崩れる）

約 30km²。

**方針: 計算対象は洛中全域とし、v1の提供エリアは可視領域の計算結果を見てから絞る。**

## 3.5 経路生成：グラフ探索は不要

碁盤の目なので、**通りの並び順の差分を取るだけ**で経路が決まる。
A* 等のグラフ探索は要らない。

```
現在地: 四条 × 烏丸     目的地: 三条 × 河原町
南北: 四条 → 三条  = N本 上ル
東西: 烏丸 → 河原町 = M本 東入ル
```

### 経路を1つに絞らない

「上ル」と「東入ル」の**実行順序は自由**。この自由度を捨てずに活かす。

> **順序の自由度を、ランドマークが見える経路を選ぶために使う。**

これにより可視領域が飾りではなく**経路選択の主役**になる。

### 例外処理

御所・二条城・寺社・市場など **通り抜けできない街区** がある。
これも座標ではなく「この区間は通れない」という**禁止区間リスト**で表現できる。

## 4. データ

### 4.1 PLATEAU 京都市

[G空間情報センター](https://www.geospatial.jp/ckan/dataset/plateau-26100-kyoto-shi-2025) にて 2022〜2025年度が公開済み。

| 項目 | 内容 |
|---|---|
| 最新 | 2025年度 |
| 建築物 | LOD0 / 1 / 2.0 / 3.3 |
| 整備範囲 | LOD1: 185.0km² / LOD2: 24.24km² |
| 形式 | CityGML, 3DTiles |
| その他 | 地形(dem)、道路(tran)、都市計画、土地利用、災害リスク、都市設備、植生、橋梁 |

### 4.2 必要なデータ

- **bldg**（建築物）— 遮蔽判定
- **dem**（地形）— 山ランドマークの可視判定に必須
- **tran**（道路）— 可視領域計算のサンプル点（道路中心線）

> **通り名データは不要。**3.5 の通り経路計算に座標を使わないため、
> PLATEAU tran の通り名属性の有無も、OSM（誰でも編集できる無料の世界地図データ）も
> 当面は必要ない。

### 4.3 通り順テーブル（座標不要・手打ち）

経路計算に必要なのは通りの**並び順**だけ。京都には数え歌があるのでそのまま使える。

```
東西の通り（北→南）: 丸竹夷二押御池 姉三六角蛸錦 四綾仏高松万五条…
南北の通り（東→西）: 寺御幸麩屋富柳堺 高間東車屋町 烏両室衣新釜…
```

この2つの配列だけで 上ル/下ル/東入ル/西入ル の本数計算が完全に成立する。

**方針: 正確な地理情報は後から与える。それまでは仮データで進める。**

| 作るもの | 座標 | 着手 |
|---|---|---|
| 通り順テーブル（南北・東西の配列） | 不要 | **今すぐ** |
| 住所パーサ（`四条烏丸上ル` → 構造化） | 不要 | **今すぐ** |
| 経路の分解（方向 × 本数、複数パターン列挙） | 不要 | **今すぐ** |
| 指示文の生成（「タワーを背にして3本上ル」） | 不要 | **今すぐ** |
| グリッドUI用の格子データ（N×M） | 不要 | **今すぐ** |
| 目的地マスタ（スポット20件程度、副入力） | 不要 | **今すぐ** |
| 交差点の実在マスク（bool行列） | 不要 | 要調査（4.5.2） |
| 通りごとの緯度経度配列 | **要** | GPS を乗せる段階で（4.6） |
| Google URL からの取り込み | **要** | **スコープ外**（4.5.3） |
| 到達判定・講評 | 不要 | 後（優先度低） |

可視性は以下のインターフェースだけ先に決め、中身はスタブにする。
本物の計算結果は後から差し替えるだけで済む。

```
isVisible(交差点, ランドマーク) -> { visible: bool, bearing: 方位, layer: L1|L2|L3 }
```

## 4.5 目的地の指定方法

**碁盤の目を模したブロック状の地図（グリッドUI）で指定する。**

- 実際の地図（航空写真・道路図）ではなく、**通り名が並んだ抽象的な格子**を表示する
- ユーザーはその格子上のブロックを選ぶ
- 地理的な地図を見せないため、コンセプト（地図を見ずに）と矛盾しない

**描画に座標は不要。** 4.3 の通り順テーブルだけで N×M の格子が引ける。

### 4.5.1 内部表現は「交差点」で固定する

UIがブロック（街区）選択でも交点選択でも、内部では交差点として保持する。

```python
Destination = { "ns": "烏丸通", "ew": "四条通" }
```

京都の住所（交差点 + 方向）と同じ構造なので、指示文生成にそのまま渡せる。
UIの選択単位が後から変わっても内部モデルを変更せずに済む。

### 4.5.2 実在マスクが必要

通りによっては全区間を走っていない（例: 錦小路は堀川以西に存在しない）。
格子には**その交差点が実在するかの真偽値マスク**が要る。

座標は不要（N×M の bool 行列）だが、**実データの調査が必要**。

### 4.5.3 Google の URL から取り込む — **スコープ外（保留）**

> **v1 では実装しない。** 目的地の指定はグリッドUI（4.5）に一本化する。

将来やる場合の想定だけ残しておく。

1. 短縮URL（`maps.app.goo.gl/...`）を展開する
2. 緯度経度を取り出す
   - URL から直接抽出（`@34.xxx,135.xxx` や `!3d` / `!4d`）
   - または Google Places API（APIキーと課金枠が必要だが堅い）
3. **緯度経度 → 交差点** に変換する（4.6）

保留の理由と注意点:

- Google が返す京都の住所は「中京区中之町565」のような**町名表記**で、
  「四条烏丸上ル」ではない。**通り名は直接もらえない**ため必ず 4.6 の座標変換を経由する
- ユーザーが共有ボタンでコピーすると短縮URLになるので、リダイレクト追跡が要る
- **この機能だけが「座標なし」の原則を破る**

### 4.5.4 副入力：プリセットのスポット

京都の店・施設の住所はもともと通り名表記なので、変換が自明。
手打ちで持てるため、URL対応より先に入れられる。

```
錦市場          → 四条通西入ル / 錦小路通
イノダコーヒ本店 → 堺町通三条下ル
```

## 4.6 緯度経度 → 交差点の変換

京都の碁盤の目は**ほぼ真北を向いている**ため、以下だけで変換できる。

- 南北の通り → **経度**の配列（通り1本につき数値1個）
- 東西の通り → **緯度**の配列（通り1本につき数値1個）

緯度経度が来たら、2つの配列を二分探索で挟み込むだけで交差点が決まる。
通りが50本ずつでも数値は100個。**全面的なジオコーダは要らない。**

```python
ns_lon = {"寺町通": 135.7692, "烏丸通": 135.7595, ...}
ew_lat = {"三条通":  35.0090, "四条通":  35.0036, ...}
```

### この仕組みが効く場面

| 用途 | 入力 | 参照 | v1 |
|---|---|---|---|
| GPSでの初期位置取得 | 端末のGPS | 2.2 | 任意 |
| ゴール時の答え合わせ | 端末のGPS | 2.3 | 後回し |
| Google URLからの目的地取り込み | URLから抽出した座標 | 4.5.3 | **スコープ外** |

**この配列は仮データで進められる。** 正確な値は後から差し替えるだけでよい。

### v1 は座標ゼロで完結できる

Google URL をスコープ外にしたことで、**座標を使う機能が v1 から消えた。**

- 目的地 → グリッドUIで選択（座標不要）
- 初期位置 → **同じグリッドUIで「今どこ？」を選択すれば座標不要**
- ゴール判定 → 後回し（優先度低）

つまり 4.6 は v1 の必須要素ではなく、**GPSを乗せる段階で初めて要る**。
バックエンドは完全に座標なしで書き切れる。

> GPSでの初期位置取得（2.2）を v1 に入れるかは要判断。
> 入れないなら v1 は地理情報ゼロで動作する。

## 8. 次の一手

地理情報の有無で2本に分け、**A を先に進める**。

### A. 座標なしで作るバックエンド（今すぐ着手可能）

1. 通り順テーブル（数え歌を配列化）
2. 住所パーサ
3. 経路の分解 → 複数パターン列挙
4. 指示文の生成
5. 目的地マスタ（スポット20件）

可視性は `isVisible()` のスタブで埋めておき、後から本物を差し込む。

### B. 可視領域の計算（正確な地理情報が入り次第）

**まず烏丸通1本から。**

京都タワーは**烏丸通の真上**（烏丸 × 塩小路、京都駅北）に建っている。
烏丸通を南向きに見ると正面にタワーが立つため、最も見えやすい線であり、
直感とも一致するのでデモとして分かりやすい。

やりやすさの順:

| 手順 | 内容 | 軽くする工夫 |
|---|---|---|
