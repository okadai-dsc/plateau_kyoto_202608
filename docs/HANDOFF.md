# Kyoter — 分担と受け渡し

## 1. 分担

| 担当 | 範囲 | ブランチ | worktree |
|---|---|---|---|
| **Codex** | バックエンド（`backend/`） | `feature/backend` | `../kyoter-backend` |
| **Claude** | フロントエンド（`frontend/`） | `feature/frontend` | `../kyoter-frontend` |

### なぜこの割り当てか

- **バックエンド → Codex**: 仕様が完全に確定していて機械的。添字計算とスキーマ準拠が中心で、
  企画意図の解釈がほとんど要らない
- **フロントエンド → Claude**: 「地図を出さない」「歩く間は画面を見せない」など、
  **企画意図の解釈が要る**。SPEC 全体の文脈が効く

### なぜコンフリクトしないか

触るディレクトリが完全に分かれている。接点は [API.md](API.md) の JSON スキーマ1枚だけ。

```
backend/    ← Codex のみ
frontend/   ← Claude のみ
mock/       ← 双方が読む（変更しない）
docs/       ← 変更する場合は要相談
```

## 2. 開始手順

### バックエンド（Codex）

```bash
cd ../kyoter-backend
```

渡すプロンプト:

> `docs/SPEC.md`（企画）、`docs/API.md`（共通契約・必読）、`docs/BACKEND.md`（作業指示）を読んで、
> `backend/` を実装してください。`docs/BACKEND.md` の「完了の目安」を満たすことがゴールです。
> `mock/grid.json` と `mock/route.json` と同じ形のレスポンスを返すこと。
> `docs/API.md` は共通契約なので変更しないでください。

### フロントエンド（Claude）

```bash
cd ../kyoter-frontend
```

渡すプロンプト:

> `docs/SPEC.md`（企画）、`docs/API.md`（共通契約・必読）、`docs/FRONTEND.md`（作業指示）を読んで、
> `frontend/` を実装してください。`docs/FRONTEND.md` の「完了の目安」を満たすことがゴールです。
> バックエンドは未完成なので `mock/grid.json` と `mock/route.json` を読んで開発すること。
> `docs/API.md` は共通契約なので変更しないでください。

---

## 3. 守ってもらうこと

| # | ルール | 理由 |
|---|---|---|
| 1 | **`docs/API.md` を勝手に変更しない** | 変えると相手の作業が壊れる。変更が必要なら双方に共有してから |
| 2 | **`mock/*.json` を勝手に変更しない** | 同上。再生成が必要なら `tools/gen_mock.py` を使う |
| 3 | **相手のディレクトリを触らない** | `backend/` と `frontend/` |
| 4 | **通り名をハードコードしない** | 仮名（`A通`/`1通`）。実データは後で差し替える |
| 5 | **通りの本数をハードコードしない** | 実データでは本数が変わる |
| 6 | **緯度経度を使わない** | v1 のスコープ外（SPEC 4.6） |
| 7 | **地図ライブラリを使わない** | 地図を出した瞬間に企画が死ぬ（SPEC 1章） |

## 4. 仮データについて

元データは **`tools/kyoto_streets.json` の1枚**。ここを編集して再生成する。

```bash
python3 tools/gen_mock.py
```

| 生成物 | 用途 |
|---|---|
| `backend/app/data/streets.json` | 通りの定義・観光地 |
| `backend/app/data/exists.json` | 実在マスク |
| `backend/app/data/visible.json` | タワー可視性 |
| `mock/grid.json` | `GET /api/grid` のモック（フロント単体開発用） |
| `mock/route.json` | `POST /api/route` のモック（フロント単体開発用） |

### 仮データの中身

Web上の公開情報（通り名数え歌ほか）から作った**実際の京都の通り**。

- 南北 32本（川端通〜千本通）× 東西 28本（今出川通〜十条通）＝ 交差点 896
- うち実在 658 — 通りの延び方を `span` で表現している
  - 錦小路通は寺町通までしか届かないので、河原町通・川端通とは交差しない
  - 京都御苑（今出川通〜丸太町通 × 寺町通〜烏丸通）で御幸町通〜車屋町通が途切れる
  - 二条城は `blocked` で表現
- うちタワー可視 73（実在の 11%）
- 観光地 11箇所（京都御苑・二条城・錦市場・東西本願寺・京都駅・東寺 ほか）

**烏丸通の南北ビスタを可視にしてある。** 実際に京都タワーが烏丸通の真上に建ち、
南北の見通しが効くのを模したもの。これにより経路選択ロジックの検証ができる。

> **まだ仮なのは2つ。** 通りの延び方（概算）と、タワーの可視性。
> どちらも SPEC 4.8 の受領データで置き換える。
> **差し替えは `tools/kyoto_streets.json` だけで済み、コードは変更不要であること。**

## 5. 統合

1. 双方が「完了の目安」を満たしたら `develop` へマージ
2. フロントの取得先をモックから `/api/*` に切り替える（1箇所のはず）
3. 通しで動作確認
4. 実データが届いたら `backend/app/data/*.json` を差し替え
